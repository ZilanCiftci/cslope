The geometry of a model is a cross-section of the slope: an **exterior boundary** around the whole section and **interior boundaries** that divide it into material regions.

<Figure media="geometry" caption="The exterior boundary of a slope with its points." />

## Exterior boundary

Open **Model › Boundaries › Exterior**. The window lists the points of the boundary in order, with their X and Y coordinates in meters.

- Type new coordinates in the table, or select the boundary on the canvas and drag its points (see [Editing on the canvas](/docs/interface#editing-on-the-canvas)). Picking a row selects that point on the canvas.
- **+ Add point** adds a point 5 m to the right of the last one.
- The button at the end of a row removes the point. The boundary keeps at least three points.

On the canvas you can also right-click an edge and choose **Add point**, or right-click a point and choose **Delete point**. <Kbd>Delete</Kbd> removes the selected point. A model imported from another program or a DXF or DWG drawing starts with its exterior and material boundaries locked; click **Unlock** in the status bar, or right-click the boundary and choose **Unlock**, to edit them on the canvas.

The top of the exterior boundary is the ground surface. Slip surfaces enter and leave the slope there.

## Interior boundaries

Open **Model › Boundaries › Interior**. Interior boundaries divide the section into regions, one material each. A boundary can be:

- an **open polyline** from one side of the section to the other, for a layer boundary, or
- a **closed polygon** (the last point equal to the first), for a lens.

**+ Add boundary** under the list creates a horizontal boundary across the model at mid-height; the **×** at the end of a row removes that boundary. Select a boundary in the list to edit its points in the table below, or click it on the canvas.

When you drag a point near a point of another line, it snaps to that point, so that boundaries meet exactly.

## Regions and materials

cSlope finds the regions between the boundaries automatically. Open **Model › Materials › Assign** to give each region a material: the window lists the regions with a material for each. You can also right-click a region on the canvas and choose **Assign material…**, or double-click it, and pick its material from the menu. A region without an assignment uses the first material in the list.

Define the materials themselves in **Model › Materials**. See [Materials](/docs/materials).

## Snapping and coordinates

The status bar has a **Snap** checkbox and a grid size from 0.1 m to 5 m. With Snap on, dragged points snap to the grid. Points always snap to points of other lines nearby. The status bar shows the cursor position in model coordinates.

## Import from DXF

**File › Import › DXF file…** reads a section from a CAD drawing and adds it to the project as a new model, named after the file.

- The **closed polyline with the largest area** becomes the exterior boundary. The drawing must contain one.
- **Open polylines on a water layer** become piezometric lines: a layer whose name contains *water*, *piezo*, *vatten* or *grundvatten*, or the word *gw* or *wt*.
- **All other polylines and lines** become interior boundaries. Lines on the same layer are joined end to end.

The drawing must be an ASCII DXF. Polylines (LWPOLYLINE, POLYLINE) and lines (LINE) are read; arcs, splines and blocks are skipped, and the import message lists what was skipped. Drawing units (mm, cm, m, inches, feet) are converted to meters.

After the import, assign materials to the regions, add the materials' properties and set the search limits before running the analysis.

<Callout type="tip">
  Draw the outline of the slope as one closed polyline, and each layer boundary as one polyline that reaches the outline at both ends.
</Callout>

## Import from DWG

**File › Import › DWG file…** reads a DWG drawing (version R11 or later) the same way: the polylines and lines of the model space are read, and the model is made from them by the same rules as from a DXF file (the outline, the water layers, the interior boundaries, the units). The model is named after the file.

- Arc segments of polylines are read as straight segments; the import message says how many polylines had them.
- Entities in paper space (layouts) are not read, and the message says how many there were. Other entity types, as for DXF, are skipped and listed.
- The message gives the file's DWG version, for example *DWG version AC1032 (2018)*.
- A file with errors is read again in a recovery mode that keeps what it can; the message then says so, with the reason, and asks you to check the imported geometry.

The reader is loaded the first time it is used. A file it cannot read gives a message with the reason, for example *Not a DWG file (it does not start with a DWG version code).*, *This DWG version is not supported: …* for a drawing older than R11, or *Reading the DWG file took more than 60 seconds; the file may be damaged.*

To place a DWG drawing under a model and pick its lines instead, see [Drawings](/docs/drawings).

## Import and export .gsz project files

**File › Import › .gsz file** reads a .gsz project file (a ZIP archive with the model as XML) and adds each slope stability analysis in it to the project as a model. The import message lists everything that did not carry over exactly; read it before running.

- **Regions** become the exterior boundary (the edges of one region), the boundaries between materials (the edges two regions share) and the region assignments. Regions without a material in the analysis are left out.
- **Materials**: Mohr-Coulomb, undrained (φ = 0), bedrock (impenetrable), high strength and the anisotropic function (c and φ times one function of the base inclination; a separate function for φ is not imported). The file's anisotropy functions are interpolated linearly between their points, and the sign of their inclination is changed: the file takes it negative where the slice base dips down in the direction of sliding, cSlope positive. Any other strength model is read as Mohr-Coulomb with the cohesion and friction angle the file gives, and the message names it with all its parameters, to be entered by hand.
- **Water**: the piezometric lines, each material on its own line, and the phreatic correction of the pore pressure when the analysis has it on. A material without a line gets a line below the model (no pore pressure). Pore pressure from a seepage analysis and rᵤ are not imported.
- **Surcharges** are a fill between a drawn line and the ground whose *unit weight* the file gives: they become distributed loads of unit weight × height above the ground, in strips where the ground or the line bends, vertical or normal to the ground as the file gives them. **Line loads** become point loads (vertical).
- **Method, number of slices, direction of sliding and entry and exit ranges** are carried over, and so are fully specified slip surfaces and the windows and end angles of a block search. When the file optimizes the critical surface after an entry and exit or block search, the **non-circular optimization** is turned on. The file's minimum slip volume and minimum slip depth become the **minimum slip area** (the volume per unit width, in m²) and **minimum slip depth** in the analysis options, and the import message gives their values. An analysis that takes its slip surfaces from another analysis gets that analysis's search and limits. Another search (grid and radius) is not: cSlope's own search over the whole slope is used.
- **Reinforcement**: anchors, nails, geosynthetics and piles become reinforcement elements and piles: anchors with their bond (a stress over π × the bond diameter) along the bonded length and the head held by the wall, nails with their bond along the whole length and the plate capacity at the head, geosynthetics with their pullout resistance as given or from the overburden (interface angle, surface area factor), piles and anchors or nails with a shear force with that force along the slip surface. "F of S dependent" elements are passive (divided by the factor of safety). A force the file distributes over the slices acts where the slip surface crosses the element; a user-defined force (a function of distance) is not imported.
- **Results**: when the file was saved after solving, its critical circle is added as a custom surface, and the message gives its factor of safety for comparison.
- Imperial files are converted to meters, kN/m³ and kPa.
- Every point of an analysis's point list is kept. Some files give two of its points the same number; the repeated one is read as the number of its place in the list, as the file's references to it are.

**File › Export › .gsz file** writes the active model as a .gsz file with one analysis: the regions, the Mohr-Coulomb, undrained, anisotropic function and bedrock materials, the piezometric lines (with the phreatic correction when the model uses it), distributed loads (as a 1 m fill of unit weight equal to the load), point loads, the method, the entry and exit ranges (with the non-circular optimization when it is on), the minimum slip area and depth (when set) and a tension crack at a limiting angle. Strength that varies with depth or datum, combined analysis, anisotropy of undrained strength, reinforcement, piles, a tension crack depth and partial factors are not written; the export message lists what was left out. Open the file in the receiving program and check it before use.

## Import and export .stix project files

**File › Import › .stix file** reads a .stix project file (a ZIP archive of JSON documents) and adds each calculation in it to the project as a model, built from the stage it calculates (the last stage of its scenario; in a file saved before 2024, the stage named like the calculation). The import message lists everything that did not carry over exactly.

- **Layers** become the exterior boundary, the boundaries between materials and the region assignments. A layer inside another (a core in a dike) is a hole in the outer one.
- **Soils**: one material per soil and state. Mohr-Coulomb (the advanced model's dilatancy ψ below φ reduces c and φ as Davis does: $c^* = c\cos\psi\cos\varphi/(1-\sin\psi\sin\varphi)$, $\tan\varphi^* = \cos\psi\sin\varphi/(1-\sin\psi\sin\varphi)$), Su (as SHANSEP, with the layer's POP, OCR or yield stress; a yield stress or OCR given at a point becomes the POP there), the Su table and the sigma-tau table (as a shear-normal function). A soil with another model above the phreatic level gets it as its **strength above the water line**.
- **State from an earlier stage**: a layer without a state of its own keeps the stress history of the latest earlier stage that has one: its yield stress is the effective vertical stress of that stage plus the POP, so lowering the water or adding a berm in a later stage raises the OCR. The earlier stage is carried with the model.
- **Water**: the phreatic line, and the head and reference lines as a **waternet** (see [Water](/docs/water)). Pore pressures from a groundwater flow mesh are not imported.
- **Loads**: uniform loads, with their **degree of consolidation** per layer (the rest of the load as excess pore pressure below the water), the degree of consolidation under the weight of layers as B̄ = 1 − the degree on the layers below (the loading layer's material as fill), line loads with their angle, and the earthquake coefficients as the seismic load. Tree loads and the spread of loads are not imported.
- **Reinforcement**: geotextiles, their strength developed over the reduction length at each end. Nails and forbidden lines are not imported.
- **Method and slip plane**: Bishop and Spencer (as Morgenstern-Price with a constant function). A given circle or slip plane is analyzed alone; after a search, cSlope searches the whole slope itself. The direction of sliding follows the file's slip plane. Uplift-Van has no counterpart: its critical slip plane is analyzed with Spencer. Design and probabilistic calculations are imported with the soils' given values; the model factor is not imported.
- **Results**: the file's critical slip plane is added as a custom surface, and the message gives its factor of safety for comparison.

**File › Export › .stix file** writes the active model as a .stix file with one scenario: the layers, soils, phreatic line or waternet, uniform loads (with their degree of consolidation), line loads, the seismic coefficients, geotextiles and the method, with a given circle (Bishop), a given slip plane (Spencer) or a search grid set from the model's extent. A model with an earlier stage is written as two stages. What is left out is listed; open the file in the receiving program and check it before use.

## Import and export .sli, .slim and .slmd model files

**File › Import › .sli/.slim/.slmd file** reads a model file in this text format (.sli), or a ZIP archive holding one (.slim) or several scenarios (.slmd, each scenario a model). The import message lists what did not carry over.

- **Geometry**: cells of the same material are merged into regions; the outer edges are the exterior boundary and the edges between materials the material boundaries (a lens is a closed boundary). Model sides leaning by less than 1/1000 of the width are made vertical.
- **Materials**: Mohr-Coulomb, undrained (constant or increasing with depth), the shear-normal function, Hoek-Brown, SHANSEP with an OCR table against elevation and the anisotropic models (as the anisotropic function), with the saturated unit weight, φb with its suction cap and the drawdown (R) envelope.
- **Water**: the water table and piezometric lines per material, Hu = 1 or automatic (the phreatic correction), the pore pressure ratio rᵤ (the water method rᵤ, or rᵤ on top of the water line), the B-bar method (B̄ on its materials, the materials without B̄ as fill, and B̄ × the loads applied in the second stage), and three-stage rapid drawdown when an R envelope is given. Pressure grids and finite element groundwater are not imported.
- **Loads and support**: distributed loads (a varying load in ten uniform steps), line loads, seismic coefficients, end-anchored bars, grouted tiebacks and geosynthetics.
- **Analysis**: the method (Bishop, else Spencer, else the general limit equilibrium as Morgenstern-Price with a half-sine function, else Janbu), the number of slices (at least 10), the direction, given circles and surfaces, slope limits as entry and exit ranges, non-circular optimization and a tension crack.
- Imperial files are converted to meters, kN/m³ and kPa.
- Every point of an analysis's point list is kept. Some files give two of its points the same number; the repeated one is read as the number of its place in the list, as the file's references to it are.

**File › Export › .slim file** writes the active model as a .slim file: the regions as triangular cells, the materials, water lines, loads, support, tension crack, method, slices and the custom surfaces or a grid of centers. What is left out is listed; open the file in the receiving program and check it before use.

## Parameters

Parameters are named values that you can use instead of numbers. Open **Model › Water & parameters › Parameters** and add parameters with a name and a value. A value can be a number or an expression.

Expressions can use numbers, parameter names, `+`, `-`, `*`, `/` and parentheses. For example, with the parameters `H = 10` and `slope = 2`, the toe of a slope can be at `X = H * slope`.

Parameters can be used in:

- the coordinates of the exterior and interior boundaries and of the piezometric lines,
- the properties of the materials,
- the magnitude and position of distributed and line loads.

Change a parameter and everything that uses it changes with it. Parameters are also the easiest way to run a [sensitivity analysis](/docs/sensitivity) of a dimension. A point coordinate given by a parameter does not move when you drag the point on the canvas.
